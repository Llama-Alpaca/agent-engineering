# DeepSeek Harness 设计决策专题：协议、所有权与演进

> 课程十三：八个设计决策案例，读上游 `99f6f02`（`dsh@0.1.0-rc.7` 附近）真实源码，并沿 `47f9438 (rc.5) → 99f6f02 (rc.7) → master` 的真实演进验证决策的代价。

## 这门课是什么（2026-08 重新定义）

与课程十二一样，本课在 2026-08 重做过一次方向修正：旧版把每个专题做成自造模拟器；新版直接读真实源码。区别在于视角——课程十二沿"一条消息穿过系统"的纵向链路读；**本课横向抽取八个设计决策，每个决策回答"当时面对什么问题、有哪些备选、选了什么、付出什么代价、演进验证了什么"**。

两个真实演进点贯穿全课：

- `47f9438`（rc.5，课程十二的快照）→ `99f6f02`（rc.7，本课快照）：111 个 commit。例证：ACP 的 admission 从 `index.ts` 长成独立的 `content.ts`；`settlePrompt` 演进为 `settleAfterQuiescence`；组装器新增 `assembled()` 统一 keep/drop 决策。
- `99f6f02` → `master`（已到 `0.1.1-rc.2`，700+ commit）：本课毕业课的素材。

## 设计主线：八个决策背后的共同压力

课程十三的八个案例表面分散（协议、SDK、投影、preset、jobs、审批、测试、演进），背后是同一组**边界压力**：当核心 spine（课程十二）稳定之后，压力转移到它与世界相接的地方——

| 无法消除的坏情况 | 决策 | 课 |
|---|---|---|
| 取消/并发随时落在协议事务中间 | 垃圾优于语义错误：宁可留下可回收的孤儿附件，不晚入队一条消息 | A00 |
| 分布式边界上"发生了什么"无法同步回答 | receipt 而非结果；归因交给持有日志的消费者 | A01 |
| 多客户端并发读同一份会话真相 | 按数据生命周期分层投影；单调 seq 是唯一并发协议 | A02 |
| 换组合会撕裂日志的解释权 | "无产出才许换"——事件溯源的数学后果，不是产品偏好 | A03 |
| 进程会死、id 会泄漏 | 授权而非保密；易失性写进 Known Limitations | A04 |
| 审批请求可能无人应答 | fail-closed 靠归一实现；未落日志的决策不算决策 | A05 |
| CI 不能没 key 就红、更不能自欺 | 五条 lane 各自声明"绝不证明什么"；结论分栏 | A06 |
| 上游在跑，课程与消费者锁着旧快照 | 演进本身当教材；锚点让"过期"从错觉变成信号 | A07 |

八课共享同一个方法论：**先承认一个无法消除的坏情况（取消竞态、进程死亡、无人应答、跨端并发），在几个都带伤的选项里选出"哪种坏是可逆的"，然后把选择的理由写进代码注释、测试用例名或 README 的 Known Limitations**。这也是"读源码能读到设计意图"的原因——上游把 why 留在了这些地方，本课只是带你逐条找到它们。
